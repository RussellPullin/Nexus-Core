## 1. Purpose

Reduce risk from production changes to Nexus Core and related services.

## 2. Requirements

1. Changes tracked in source control with description.  
2. Higher-risk changes (auth, billing, data model, permissions) get explicit testing notes.  
3. Prefer staged deploy / quick rollback path.  
4. Emergency changes allowed for active incidents; document after the fact within 48 hours.  
5. Customer-notice for material downtime when practicable.

## 3. Mobile releases

App Store releases follow Apple review; note version and user-facing changes in release notes.
